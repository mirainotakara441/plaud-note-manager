# Gmail 連携のセットアップ手順

キャリアOS が Gmail の「転職」ラベルを毎日読み取れるようにするための、1回きりの設定手順です。
所要時間はおよそ 20〜30 分です。

このアプリが要求する権限は **読み取り専用（`gmail.readonly`）だけ** です。
メールの送信・削除・ラベル変更はできない設定になっています。

- ターミナル（`npm run` が実行できる状態）

## 手順1. Google Cloud Console でプロジェクトを作成する

1. [Google Cloud Console](https://console.cloud.google.com/) を開きます。
2. 画面上部のプロジェクト選択（Google Cloud のロゴの右隣）をクリックし、**［新しいプロジェクト］** を選びます。
3. プロジェクト名に `career-os` と入力し、**［作成］** をクリックします。
4. 作成が終わったら、画面上部のプロジェクト選択が `career-os` になっていることを確認します。

> **ここで控えるもの**
> プロジェクト名（`career-os`）。以降の手順すべてを、このプロジェクトを選んだ状態で行います。
> 別のプロジェクトを選んだまま作業すると、作った設定が見つからなくなります。

---

## 手順2. Gmail API を有効化する

1. 左のメニューから **［APIとサービス］→［ライブラリ］** を開きます（[直接開く](https://console.cloud.google.com/apis/library)）。
2. 検索窓に `Gmail API` と入力して検索します。
3. 検索結果の **「Gmail API」** をクリックします。
4. **［有効にする］** をクリックします。

> **ここで控えるもの**
> 特にありません。「APIが有効です」と表示されれば完了です。

---

## 手順3. OAuth 同意画面を設定する（★ここに罠があります）

1. 左のメニューから **［APIとサービス］→［OAuth 同意画面］** を開きます（[直接開く](https://console.cloud.google.com/apis/credentials/consent)）。
2. User Type で **［外部］** を選び、**［作成］** をクリックします。
3. 以下を入力します。
   - アプリ名: `キャリアOS`
   - ユーザーサポートメール: `mirainotakara441@gmail.com`
   - デベロッパーの連絡先情報: `mirainotakara441@gmail.com`
4. **［保存して次へ］** をクリックします。
5. 「スコープ」の画面は何も追加せず、**［保存して次へ］** をクリックします。
   （実際に使うスコープは、後の手順5でツールが直接要求します。）
6. 「テストユーザー」の画面で **［+ ADD USERS］** をクリックし、
   `mirainotakara441@gmail.com` を追加して **［保存して次へ］** をクリックします。

### ★ 重要：「公開」ステータスに切り替えてください

ここまでの設定だと、OAuth 同意画面は **「テスト」** というステータスになっています。
テストステータスのままだと、**取得した refresh token が7日で失効します。**
失効すると毎日の自動取込が黙って止まり、`invalid_grant` というエラーになります。
実運用では必ず以下を行ってください。

1. **［OAuth 同意画面］** の画面に戻ります。
2. 「公開ステータス」の欄にある **［アプリを公開］（PUBLISH APP）** をクリックします。
3. 確認ダイアログで **［確認］** をクリックします。
4. ステータスが **「本番環境」（In production）** になったことを確認します。

> **審査（verification）は不要です。**
> 使うスコープが `gmail.readonly` のみで、利用者が自分自身だけであれば、
> 「公開」にしても Google の審査に出す必要はありません。
> 認可時に「このアプリは Google で確認されていません」という警告が出ますが、
> **［詳細］→［（アプリ名）に移動］** から先へ進めます。
> 自分で作ったアプリなので問題ありません。

> **ここで控えるもの**
> 公開ステータスが「本番環境」になっていること。ここを飛ばすと1週間で必ず壊れます。

## 手順4. OAuth クライアントID を作成する

1. 左のメニューから **［APIとサービス］→［認証情報］** を開きます（[直接開く](https://console.cloud.google.com/apis/credentials)）。
2. 画面上部の **［+ 認証情報を作成］→［OAuth クライアント ID］** をクリックします。
3. アプリケーションの種類で **［デスクトップ アプリ］** を選びます。
   - ここを「ウェブアプリケーション」にしないでください。
     取得ツールは `http://localhost:53682/callback` で認可コードを受け取りますが、
     デスクトップアプリのクライアントであればこの localhost 受け取りが無条件で許可されます。
4. 名前に `career-os-cli` と入力し、**［作成］** をクリックします。
5. 「OAuth クライアントを作成しました」というダイアログが表示されます。

> **ここで控えるもの（2つ）**
> - **クライアント ID**（`〜.apps.googleusercontent.com` で終わる文字列）
> - **クライアント シークレット**（`GOCSPX-` で始まる文字列）
>
> このダイアログを閉じてしまっても、［認証情報］の一覧から
> `career-os-cli` をクリックすればいつでも再表示できます。

## 手順5. refresh token を取得する

1. ターミナルで、このアプリのディレクトリに移動します。

   ```bash
   cd /Users/YOSHII/Claude/Code/apps/career-os
   ```

2. 取得ツールを実行します。

   ```bash
   npm run gmail:token
   ```

3. クライアント ID とクライアント シークレットの入力を求められるので、
   手順4で控えた値をそれぞれ貼り付けて Enter を押します。
4. ブラウザが自動で開き、Google のアカウント選択画面が表示されます。
   `mirainotakara441@gmail.com` を選びます。
5. 「このアプリは Google で確認されていません」と出た場合は、
   **［詳細］→［キャリアOS（安全ではないページ）に移動］** をクリックします。
6. 「Gmail のメールを表示する」という権限の確認画面で **［続行］** をクリックします。
7. ブラウザに「認可が完了しました」と表示されたら、そのタブは閉じてターミナルに戻ります。
8. ターミナルに次の形式で1行表示されます。

   ```
   GMAIL_REFRESH_TOKEN=1//0e....................
   ```

> **ここで控えるもの**
> `GMAIL_REFRESH_TOKEN=` から始まる1行そのもの。
> このツールはトークンをファイルに書き込みません（うっかりコミットしてしまう事故を防ぐため）。
> ターミナルの表示が流れてしまう前にコピーしてください。
>
> もし `refresh_token が返ってきませんでした` と表示された場合は、
> [Google アカウントの権限管理](https://myaccount.google.com/permissions) から
> 「キャリアOS」のアクセス権を削除してから、もう一度手順5をやり直してください。

## 手順6. 環境変数に登録する

### 6-1. ローカル（`.env.local`）

このアプリのディレクトリに `.env.local` を作り（既にあれば追記し）、以下を書きます。

```
GMAIL_CLIENT_ID=（手順4のクライアントID）
GMAIL_CLIENT_SECRET=（手順4のクライアントシークレット）
GMAIL_REFRESH_TOKEN=（手順5で表示された値）
GMAIL_LABEL_ID=Label_82
GMAIL_MAX_RESULTS=60
```

`.env.local` は `.gitignore` に入っているため、Git にはコミットされません。

### 6-2. Vercel

1. [Vercel のダッシュボード](https://vercel.com/dashboard) で `career-os` プロジェクトを開きます。
2. **［Settings］→［Environment Variables］** を開きます。
3. 以下の変数を1つずつ追加します。Environment は **Production / Preview / Development のすべて** にチェックを入れます。

   | Key | Value |
   | --- | --- |
   | `GMAIL_CLIENT_ID` | 手順4のクライアントID |
   | `GMAIL_CLIENT_SECRET` | 手順4のクライアントシークレット |
   | `GMAIL_REFRESH_TOKEN` | 手順5で表示された値 |
   | `GMAIL_LABEL_ID` | `Label_82` |
   | `GMAIL_MAX_RESULTS` | `60` |
   | `CRON_SECRET` | 任意の長いランダム文字列（後述） |

4. 追加後、**再デプロイ** してください（環境変数は再デプロイしないと反映されません）。

> **`CRON_SECRET` について**
> 日次の取込エンドポイント `/api/cron/ingest` を無関係な人に叩かれないための合言葉です。
> ターミナルで次のコマンドを実行すると、貼り付けやすい値が作れます。
>
> ```bash
> openssl rand -hex 32
> ```
>
> Vercel Cron はこの値を `Authorization: Bearer 〜` として自動で付けてくれるので、
> 環境変数に登録するだけで設定は完了です。
> **未設定のままだと取込エンドポイントは 503 を返して動きません**（安全側に倒してあります）。

## 動作確認

環境変数を登録して再デプロイしたら、以下で確認します。

1. キャリアOS にログインし、`/api/ingest` に POST して取込を1回走らせます。
   （UI にボタンがある場合はそちらから。無ければブラウザの開発者ツールのコンソールで
   `fetch("/api/ingest", { method: "POST" }).then(r => r.json()).then(console.log)` を実行します。）
2. `/api/ingest` を GET すると、直近10回の実行ログが返ります。
   `fetched` / `new_emails` / `new_jobs` の数字が増えていれば成功です。

## うまくいかないときの確認ポイント

| 症状 | 原因として多いもの |
| --- | --- |
| `invalid_grant` が出る | OAuth 同意画面が「テスト」のままで、7日経って refresh token が失効した（→ 手順3の「公開」に切り替え、手順5をやり直す） |
| 401 が返る | `CRON_SECRET` が Vercel と Cron の設定でずれている |
| 503 が返る | `CRON_SECRET` が未設定 |
| 取り込まれるメールが0件 | `GMAIL_LABEL_ID` が違う。ラベルIDは Gmail API の `users.labels.list` で確認できる |
| 日本語が文字化けする | このアプリ側では UTF-8 デコードを明示しているため通常は起きない。起きた場合は報告してください |
