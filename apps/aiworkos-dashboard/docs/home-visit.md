# 家庭訪問（/home-visit）

ライフOS側の信仰ブロック。壮年部・男子部を**人ベース**で見て、
「いつ訪ね／会えたか／どんな話をしたか」を残し、次に行く先を決めるページ。
仕事の記録ではないので、団体・案件まわり（organizations / weekly_reports 等）とは意図的につないでいない。

## テーブル

### home_visit_members（1行＝1人）

| 列 | 用途 |
| --- | --- |
| name / division / district / block / role | 名簿の氏名・部・地区・ブロック・役職 |
| birth_date | 分かる人は生年月日。**年齢は表示時に毎回計算する**（登録時の値を持つと毎年ズレるため） |
| age_manual | 生年月日が分からない人だけ、年齢を直接入れる。birth_date を入れた時点で捨てられる |
| address | 名簿の表記のまま（「要町2-25-1」「千早2-41-1コーシャハイム千早306」）。地図用の整形は `mapsQuery` が行う |
| note | 「訪問不可」など訪問の可否に関わる注意。名簿の住所欄にあった「不在」「収監中」は載せない（下記） |
| active | false＝休止（一覧から外すが訪問履歴は残す）。転出・長期不在はこちら |
| sort_order | 表示順。名簿の並びをそのまま入れてある |

### home_visit_logs（1行＝1回の訪問）

`met` の3値が状態そのもの。**予定と実績で行を分けない**（予定の行に後から met を入れるとそのまま実績になる）。

| met | 意味 |
| --- | --- |
| null | これからの予定（まだ行っていない） |
| true | 会えた |
| false | 会えなかった（留守・不在） |

日付が過ぎても met が null のままの行は、記録し忘れとして「これからの予定」に残り続け、
一覧では「未記録」と赤く出る（消えると気づけないため、あえて残す）。

## 初期データ

`2026-07-18_城西支部_地区名簿（要希望・旭日・平和）_v01_現行.xlsx` の
「壮年部一覧」「男子部一覧」から81名（壮年部54・男子部27）を投入済み。

- 取り込んだのは氏名・部・地区・ブロック・役職・生年月日・住所。
  **電話番号は入れていない**（訪問には要らないため。増やすなら都度考える）。
- 名簿の住所欄には住所でない値も入っている（「不在」11名・「収監中」1名）。
  **これらはどこにも載せない**（2026-08-02 吉井さんの判断）。住所として入れると地図が壊れ、
  備考へ回しても本人の状況が画面に出続けてしまうため、住所を空にするだけにしてある。
  次に名簿を取り込む時も、住所欄を機械的に住所として入れず、住所でない値は捨てる。
- 名簿の生年月日は書式がバラバラ（`S18.02.13` / `S.28.01.18` / `S44・1・31` / `S.35.1126`）。
  元号＋数字だけを拾って西暦に直し、名簿の年齢列と突き合わせて検算した（壮年部52名が一致、
  残り2名は名簿作成日 7/18 以降に誕生日が来ただけ）。
- 読めなかった2名は生年月日を空にして note に理由を入れてある（鈴木創さん・花岡昌大さん）。
  ページ上では「年齢不明」と出るので、分かった時点でメンバー編集から入れる。

## 認証

書き込みは `lib/homeVisitAuth.ts`＝合言葉cookieのみ。ファミリーと違い Bearer（iPhoneショートカット）経路は
用意していない。読み取りは anon キー＋RLS（SELECTのみ）で、他のライフOSページと同じ。

## Googleマップ連携

名簿の住所は市区町村が省かれ（「要町2-25-1」）、建物名・部屋番号がくっついている
（「千早2-41-1コーシャハイム千早306」）。そのまま地図に投げると別の土地に飛ぶので、
`lib/homeVisit.ts` の `mapsQuery` が**地図に渡す時だけ**整形する。DBは名簿の表記のまま持つ
（一覧では短い方が読みやすいため）。

整形のルール（実データ67件で検算済み）：

1. 空白の手前まで／番地の並び（`2-41-1`）までで切る＝建物名と部屋番号は落とす
2. 都道府県から始まればそのまま、`◯◯区` から始まれば `東京都` を足す
3. どちらでもなければ地元とみなして `東京都豊島区` を足す（名簿の大半が要町・千早のため）
4. 番地が無い住所（「埼玉県」「板橋区」だけ）は `null`。リンクを出さず、その旨を出す

リンクは3種類：

- 1人のカード … `🗺 地図で見る`（search API）と `🚶 ここへの道順`（dir API・徒歩）
- 「これからの予定」の各行 … `🗺`（その1軒だけ）
- 「これからの予定」の日付ごと … `🚶 この日の順路`。その日に回る先を並び順のまま
  経由地にした1本の経路にする（Googleマップの経由地上限に合わせて10軒まで）
