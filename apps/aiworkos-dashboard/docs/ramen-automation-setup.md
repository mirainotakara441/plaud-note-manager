## 1. Xの開発者キーを取る（本人作業・10分）

2026年2月からXのAPIは従量課金に変わっている。サブスクではなく使った分だけ。

- 投稿1本 **$0.015**
- 本文にURLが入る投稿 **$0.20**（13倍。なので本文にリンクを入れない設計にしてある）
- 最低利用料・契約なし

月16〜25杯ペースなら **月40円前後**。

1. https://console.x.com を開いて @0kara1_man でログイン
2. アプリを作る（名前は何でもよい。例：`aiworkos-ramen`）
3. **User authentication settings** で権限を **Read and write** にする
   （ここを Read のままにすると投稿だけ落ちる。よくある詰まりどころ）
4. **Keys and tokens** から次の4つを控える
   - API Key
   - API Key Secret
   - Access Token
   - Access Token Secret
5. クレジットを購入する（少額でよい。$5でも300本以上投稿できる）

> Access Token は権限を Read and write に変えた**後**に再発行すること。
> 変更前に発行したトークンは Read のままで、投稿時に 403 が返る。

## 2. 環境変数を入れる

`.env.local`（ローカル）と Vercel の Environment Variables の両方に。

```
X_API_KEY=...
X_API_SECRET=...
X_ACCESS_TOKEN=...
X_ACCESS_TOKEN_SECRET=...
RAMEN_CAPTURE_SECRET=（適当な長い文字列。iPhoneショートカット用の合言葉）
```

4つが揃うまで、`/ramen` の「Xへ投稿」ボタンは
「Xのキーが未設定です」と返すだけで何も起きない（フェイルクローズ）。

## 3. iPhoneショートカットを作る（本人作業・15分）

ショートカット名は「ラーメン記録」あたりで。中身は4アクション。

1. **写真を選択**（複数選択オン）
2. **アルバムに追加** → アルバム「ラーメン」
   ※ ここで今まで手でやっていたライブラリ整理が消える
3. **テキストを要求** ×3
   - 「店名」
   - 「注文したもの」
   - 「ひとこと」← マイクで喋って入れる。ここが文章の一次情報になる
4. **URLの内容を取得**
   - URL: `https://<AIワークOSのURL>/api/ramen/capture`
   - 方法: POST
   - ヘッダ: `Authorization` = `Bearer <RAMEN_CAPTURE_SECRET>`
   - 本文: JSON
     ```json
     { "shop": "（店名）", "menu": "（注文）", "memo": "（ひとこと）" }
     ```

写真も一緒に送るなら、**Base64エンコード**したうえで
`/api/ramen/photo` に `{ "id": <capture が返した id>, "data": "...", "content_type": "image/jpeg" }`
を1枚ずつPOSTするアクションを足す。写真はSupabaseの非公開バケットに入り、
X投稿時にサーバーが取り出して自動で添付する。

## 4. 実際の運用

| いつ | やること | かかる手数 |
|---|---|---|
| 店を出た直後 | ショートカットを叩く（写真＋店名＋注文＋ひとこと） | 1回 |
| 帰りの電車 | `/ramen` を開き「文章を作る」 | タップ1回 |
| 同上 | X用を確認して「Xへ投稿」 | タップ1回 |
| 同上 | 食べログ用は「本文をコピー」→店ページで貼る→点数を付けて投稿 | 貼り付けのみ |
| 月初 | `/ramen` の「4本つくる」→ 4本コピーしてXへ | タップ1回＋貼り付け |

食べログだけ半自動にしてあるのは、公式APIが2014年に終了していて存在しないこと、
そして料理・サービス・雰囲気・CPの4項目は最後は本人が決めるものだから。

## 7. 検証用スクリプト

```bash
node scripts/verify-x-keys.mjs                          # 投稿せずにキーと署名だけ確認
node scripts/test-x-post.mjs <画像パス> "<本文>"          # 写真つきで1本投稿
node scripts/test-x-post.mjs --delete <投稿ID>           # その投稿を消す
```

`verify-x-keys.mjs` は読み取り1回ぶんしか使わず、タイムラインには何も出ない。
401ならキーか発行順序、403なら権限、402/429ならクレジットの問題。

## 8. Xのメディアアップロードの落とし穴（実機で確定）

`/2/media/upload` は**multipart/form-data しか受け付けない**。ここで3回踏んだ。

- クエリ文字列に積む → `400 The query parameter [total_bytes] is not one of []`
- `application/x-www-form-urlencoded` → 同じく400
- INIT/APPEND/FINALIZE の分割方式を画像に使う → `400 Missing media field in JSON`

**画像は `media` フィールドに丸ごと入れて1回で送るのが正解**。分割方式は動画や大きい
ファイル向け。またmultipartのボディは OAuth 1.0a の署名対象外なので、署名は `oauth_*`
だけで組む。この形は `lib/x.ts` の `uploadMedia()` に反映済み。

## 5. なぜこの形か（設計メモ）

- **記録と投稿を1行に束ねている**（`ramen_logs`）。食べた事実・食べログの口コミ・Xの投稿が
  別々の場所にあると必ず食い違うため、最初から同じ行に持たせた。
- **文体は説明せず実物を見せている**。`lib/ramen.ts` の型に加えて、直近の投稿済み3件を
  そのままプロンプトに渡す。文体ルールの箇条書きだけだと「AIが書いた食レポ」になる。
- **月次は4本立て**。まとめ／特徴／金賞・殿堂／思い出の4枚。過去の実投稿は
  `ramen_monthly_posts` に入れてあり、これが生成の手本になる。
- **杯数は本人の数え方が正**。`bowl_label` に「121杯目③」のような枝番を原文のまま残している。
