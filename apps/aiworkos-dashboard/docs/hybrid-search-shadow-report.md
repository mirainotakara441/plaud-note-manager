## 何を作ったか

- `match_memory_chunks_v3` … 現行のベクトル検索（v2）に pgroonga の日本語全文検索を
  RRF（k=60）で融合した並走用関数。service_role のみ。
  scorecard W3 の宿題「ベクトル＋全文」への着手。tsvector でなく pgroonga なのは、
  Postgres 標準の tsvector が日本語を分かち書きできないため。
- `memory_chunks_pgroonga_idx` … title+content の全文索引
- `scripts/shadow-hybrid-search.mjs` … 再実行可能な比較ハーネス
- マイグレーション: `supabase/migrations/20260913000002_hybrid_search_shadow.sql`
  （rollback 手順はファイル冒頭に記載。v2 とその索引には一切触れていない）

## 実測結果（12クエリ・各 top8 比較）

### 固有名詞・数字系 8クエリ — v3 の圧勝

| 指標 | 結果 |
|---|---|
| クエリ語を含む行が増えたクエリ | **8 / 8**（減ったもの 0） |
| v3 が新たに上位8へ入れた行 | 30行 — **全30行がクエリ語を含む。ノイズ 0** |
| 応答時間 | v2 平均211ms / v3 平均116ms（劣化なし） |

象徴的な例:
- **「内本部長」** … v2 は該当語を含む行が **0件**（東洋紙業の決裁キーパーソンなのに）。
  v3 は5件、うち週報 8/31週の東洋紙業行を1位で獲得
- **「岸和田市」** … v2 は0件 → v3 は週報 8/17週の岸和田市行を獲得
- **「郵便料金 値上げ」** … 3件 → 8件（制度転換の会議録・提案スライドを獲得）
- **「アイフル」** … 1件 → 5件（進捗リカバリー計画の会議録を獲得）

これは /ask のツール定義に「1回で引けなければ言い換えて引き直せ」と書かざるを
得なかった弱点そのもの。**短い固有名詞は gte-small の埋め込み空間で潰れており、
ベクトル単独では構造的に届かない**ことが数字で出た。

### 意味検索系 4クエリ — 大きく入れ替わる。良化が優勢だが目視確認が要る

重なりは 2〜4/8 で、順位はかなり入れ替わる。入れ替わりの中身:
- 良い例:「決裁が通らない理由」で、営業実戦QA **B-12「現場から要望が上がっていない」**
  （まさにこの反論への切り返し）が全文1位で浮上。押し出されたのは類似度0.88前後の
  汎用メモ・スライド断片
- 怪しい例:「体調と仕事の両立」で、語の一致だけで日記（入学式）が混ざる

### 既知の癖（正直に書く）

- N-gram なので部分文字列に反応する。「内本部長」で学会の「竹内本部長」も引っかかった
  （文脈次第では有用だが、別人)。完全一致ではなく「語を含む」であることを忘れない
- RRF はベクトルと全文を等価に扱う。意味検索でのノイズが気になる場合、
  全文側の重みを下げる版（例: vec 1.0 / text 0.7）が次の調整候補
