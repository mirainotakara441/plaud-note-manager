済 — 7〜9月
記憶層の作り直しと、運用・セキュリティ層の完成
Memory 2.0（8/28〜29）で同一性の土台を作り直し、書き込み・読み込みをそれぞれ1本の口に絞った。運用層は合言葉ゲート・job_heartbeats・service_health・OS Guardian・毎朝の参謀・test:all（10段）・E2Eまで揃って完了。
いま — 次の一手
夜間参謀最優先
毎晩、日記・週報・会議・健康を領域横断で読んで翌朝の示唆を生成し、採用／見送りの判断を記録する。目標は「エージェントが自ら考えるOS」で、足りていないのは機能ではなく構造 ──（a）AIが能動的に起動される場所がゼロ（cron 2本はどちらもLLMを呼ばない）（b）AIが自分で追加調査する手がゼロ（tool use はリポジトリ全体で未使用、資料取得は固定件数の決め打ち）（c）出した示唆の採否・成否が記録されない。夜間参謀は（a）と（c）を同時に埋める。
次 — W3の残り
検索精度の底上げ（残りの半分）
400字チャンクでの再投入は完了（AGENTS.mdで全登録経路の厳守を明文化）。残るのはハイブリッド検索（ベクトル＋全文）と生成ログの記録で、どちらも未着手（tsvectorはリポジトリに0ヒット）。あわせてlib/chunker.ts と documents テーブルの配線 ── どちらも死蔵で、今は「切り方を変えて再生成する」という切り札が使えない。
その次
W4 朝ブリーフ連動・商談準備パック
CTOレビューが挙げた「毎日見たくなる」の答え。dx_newsのテーマ再設計＋月曜の週次ダイジェストと合流させ、朝いちで開く画面にする。夜間参謀の出口としても効く。
中期
Phase 4 残エージェント ＋ Manus統合
提案・壁打ち・武器生成・月報ドラフトは本番稼働。残る日記分析／健康管理／官民連携・新規事業の3種を必要度の高い順にプラグイン化。Manus成果物（法人請求）をDrive/Notion経由で記憶層へ取り込み検索可能に（いずれも未着手）。
構想 — V3
受注／失注を記憶に戻す自己改善ループ
提案の結果（受注・失注とその理由）を記憶へ戻し、次の提案の精度を上げる循環。設計書の「⑦振り返りが①収集の質を高める」を提案業務で回す姿。現在コード上に経路は存在しない（未着手）。※画像PDFのOCR・Typeless連携は必要になった時点で着手（据え置き）。
